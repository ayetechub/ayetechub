Developer Information

Technical details about how AYE Marketplace is built.

Platform

  • Mobile app: Android (Android 8.0 / Oreo and above). Built with Flutter for a fast, native-feeling experience from a single codebase.
  • Package ID: com.ayetechub.ayemarket
  • Website: static HTML/CSS/JavaScript, no framework, hosted on GitHub Pages.

Backend & infrastructure

ServiceRole
Cloud FirestorePrimary database — profiles, listings, chats, applications, requests
Firebase AuthenticationEmail/password, phone (OTP), and Google sign-in
Firebase StoragePhotos, CVs, verification documents, payment receipts
Firebase Cloud FunctionsServer-side automation — approvals, notifications, moderation sweeps, subscription/promotion activation
Firebase Cloud MessagingPush notifications
Google Play BillingIn-app purchase infrastructure (available for future automated payments)

Architecture

The app follows a feature-based clean architecture (domain / data / presentation layers per feature) with Riverpod for state management and go_router for navigation. Firestore security rules and Cloud Functions enforce a strict trust boundary: sensitive state changes — activating a subscription, deleting an account, moderating a listing — are only ever performed server-side by an Admin-SDK Cloud Function after a human admin's explicit action, never trusted directly from the client.

Third-party APIs & services in use

  • Firebase (Google) — authentication, database, storage, messaging, functions
  • Google Sign-In — optional sign-in method
  • Google Maps / location services — GPS-based search and the interactive map
  • Google Play Billing — reserved for future automated subscription payments
  • WhatsApp, SMS, and Phone dialer — via standard device deep links, not a hosted API

Full detail on what each service processes is in our Privacy Policy.

Reporting a security issue

If you've found a security vulnerability in AYE Marketplace or ayetechub.com, please report it responsibly to ayetechub@gmail.com with as much detail as possible (steps to reproduce, affected endpoint/screen, potential impact). Please don't publicly disclose a vulnerability before we've had a reasonable chance to address it. We appreciate responsible disclosure and will credit researchers who report valid issues, with permission.
